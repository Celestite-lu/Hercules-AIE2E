# 项目全档案（面试复习版）— 「录制即用例」

> 这套文档怎么用：**面试复习的主库**。七份档案按知识域拆分，每份都是同一种复习结构——60 秒主线（这个域被要求"讲一下"时整段可背）→ 决策速答卡（每张 30-60 秒口语回答 + 追问预案）→ 踩坑故事卡（每张 45-60 秒完整故事 + 收尾金句）→ 必背数字。
> 配套关系：`interview/resume.md` §0 术语表（十个词先弄懂）→ `interview/qa-bank.md`（40 题问答操练）→ 本档案（底层理解与故事储备）。背 qa-bank 答不上"为什么"的时候，来这查。
> 数字纪律：本档案是汇总层，与一手报告不一致时以一手报告（round1-4、experiment-report）为准。

## 0. 三遍复习法（建议路径，共约 3 小时）

1. **第一遍·数字与口径（40 分钟）**：过一遍下面"项目一页纸" + 每份档案的 §5 必背数字表。目标：任何数字被追问，3 秒内说出含义和口径。
2. **第二遍·决策与主线（80 分钟）**：每份档案背 §2 的 60 秒主线 + 通读 §3 决策速答卡（不必逐字背，记住"为什么+否决过什么"的骨架）。目标：被问"为什么这么做"时不停顿。
3. **第三遍·故事（60 分钟）**：每份档案挑 §4 排在前面的故事卡练口述，每张掐表 45-60 秒讲完。目标：三个王牌故事（快照归因缺陷、max_tokens 无效改进、81.6% 锚点更正）闭眼能讲。

## 1. 项目一页纸（30 秒版全貌）

**做什么**：把"手动点一遍页面"变成可维护的测试资产——录制 → 蒸馏 → 语义执行 → 失败归因，四条命令串起全链路。解决前端测试两大痛点：用例生产贵（录制即得）、selector 腐烂（语义执行不看 id）。

**架构一句话**：录制器（注入式 JS，事件流 JSON）→ 蒸馏器（确定性规则模板出 Gherkin 骨架，零 LLM；LLM 只润色且过事实回查）→ 执行内核（开源 Hercules：LangGraph planner→executor→assertion，语义元素表定位）→ 归因器（13 条错误签名规则优先，LLM 摘要强制引用证据、程序回查、查无此证强制降级）→ 子进程编排 CLI。

**贡献边界**：执行内核是开源上游 Hercules（AGPL）；录制器、蒸馏器、评测框架、归因器、编排 CLI、benchmark 全套 harness 与引擎改进补丁（flag 化默认 off + golden 锁定）、全部实验设计为本人增量。代码全在 `record2gherkin/` 包，上游主包不动。

**两个硬数字**：
1. 受控变异实验（6 流程 × 5 变异 × 2 方法 = 60 格，单 demo 单模型）：标识符随机化下语义执行 6/6 vs selector 基线 0/6，主指标 1.00 vs 0.667；文案改写 5/6 如实报为概率性边界。
2. MiniWoB++ browsergym registry 全量 125 任务类四轮迭代：43.2% → 46.4%（干净口径 47.8%）→ 47.2% → **61.6%**（越出零样本、只读 DOM 口径公开可比带 47-60% 的上沿）；官方=干净口径、零无效格；每轮逐格归因、前后双安全审查、五类作弊扫描全零。

**工程底盘**：492 条 pytest 全绿（recorder 21 / distiller 68 / evaluation 77 / attributor 81 / cli 54 / benchmark 191）；每模块 plan/spec/review/test-report 四件套固化于 dev_docs；引擎改动全部 flag 化、默认关闭、off 档 golden 逐字节锁定。

**时间线**：2026-09-20 立项 → 09-21 五模块开发完成合入 → 09-21/22 变异实验 exp001 定局 → 09-22~24 四轮基准迭代至 61.6% 冻结 → 09-24 面试材料+演示视频+红队复审 → 10-10 本全档案汇总并改版为复习版。
